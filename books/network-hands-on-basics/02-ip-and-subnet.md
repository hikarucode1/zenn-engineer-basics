## この章のゴール

第1章では、IP アドレスに付いていた `/24` を「おまじない」のまま使いました。この章では、この `/24` を変えて、通信できたりできなくなったりする様子を確かめます。

章を読み終えると、次の2つに答えられるようになります。

- 2つの IP アドレスが「**同じネットワーク**」にあるとは、どういうことか
- 設定が**片方だけ**間違っていると、どんな症状になるか

## 2-0. 準備 —— 第1章の2台を作り直す

第1章の最後で片付けたので、同じ2台をもう一度作ります。

```bash
sudo ip netns add pc1
sudo ip netns add pc2
sudo ip link add veth-pc1 type veth peer name veth-pc2
sudo ip link set veth-pc1 netns pc1
sudo ip link set veth-pc2 netns pc2
sudo ip netns exec pc1 ip addr add 192.168.0.1/24 dev veth-pc1
sudo ip netns exec pc2 ip addr add 192.168.0.2/24 dev veth-pc2
sudo ip netns exec pc1 ip link set veth-pc1 up
sudo ip netns exec pc2 ip link set veth-pc2 up
```

`ping` が通ることを確かめておきます。

```bash
sudo ip netns exec pc1 ping -c 1 192.168.0.2
```

```text
PING 192.168.0.2 (192.168.0.2) 56(84) bytes of data.
64 bytes from 192.168.0.2: icmp_seq=1 ttl=64 time=0.019 ms

--- 192.168.0.2 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
rtt min/avg/max/mdev = 0.019/0.019/0.019/0.000 ms
```

## 2-1. IP アドレスは 32 個の 0 と 1

`192.168.0.1` は、人間が読みやすいように書いた形です。コンピュータの中では、IP アドレス（IPv4）は **0 と 1 が 32 個並んだ数** として扱われています。

Ubuntu に最初から入っている Python で、実際に 0 と 1 の並びに直してみましょう。

```bash
python3 -c 'import ipaddress; print(format(int(ipaddress.ip_address("192.168.0.1")), "032b"))'
```

```text
11000000101010000000000000000001
```

この 32 個を 8 個ずつに区切り、それぞれを 10 進数に直して `.` でつないだものが、見慣れた `192.168.0.1` です。

| 区切り | 2進数 | 10進数 |
|---|---|---|
| 1つ目 | `11000000` | 192 |
| 2つ目 | `10101000` | 168 |
| 3つ目 | `00000000` | 0 |
| 4つ目 | `00000001` | 1 |

8 個の 0/1 で表せるのは 0〜255 なので、IP アドレスの各数字は 255 を超えません。

## 2-2. `/24` は「前から 24 個がネットワークの番号」

IP アドレスの 32 個の 0/1 は、**前半と後半で役割が違います**。

- **前半（ネットワーク部）**：どのネットワークに属しているか。住所でいえば「町名」
- **後半（ホスト部）**：そのネットワークの中の何番目の機器か。住所でいえば「番地」

前半と後半の**境目を示すのが `/24`** です。「前から 24 個がネットワーク部」という意味で、これを**プレフィックス長**と呼びます。

```text
192.168.0.1/24

        ネットワーク部（前から24個）    | ホスト部（残り8個）
2進数   11000000 10101000 00000000   | 00000001
10進数  192      168      0          | 1
```

`/24` の場合、前の3つの数字（`192.168.0`）が町名、最後の数字（`1`）が番地です。**町名が同じなら「同じネットワーク」** です。

| IP アドレス | 町名（ネットワーク部） | 同じネットワーク？（`192.168.0.1/24` から見て） |
|---|---|---|
| `192.168.0.2` | `192.168.0` | 同じ |
| `192.168.0.200` | `192.168.0` | 同じ |
| `192.168.1.2` | `192.168.1` | **違う** |

町名だけを取り出し、番地を全部 0 にしたものを**ネットワークアドレス**と呼び、`192.168.0.0/24` のように書きます。第1章で見たルーティングテーブルの1行目を、もう一度見てみましょう。

```bash
sudo ip netns exec pc1 ip route
```

```text
192.168.0.0/24 dev veth-pc1 proto kernel scope link src 192.168.0.1
```

「`192.168.0.0/24`（町名が `192.168.0` の宛先）へは、`veth-pc1` から直接送る」と書いてあります。`pc1` が IP アドレスを付けたときに、**自分と同じ町の相手には、ケーブルの先に直接いるはずだ**と考えて、この道を自動で書き足したのです。

### Linux に直接聞く —— `ip route get`

「この宛先には、どの道を使う？」は、`ip route get` で Linux に直接聞けます。

```bash
sudo ip netns exec pc1 ip route get 192.168.0.200
```

```text
192.168.0.200 dev veth-pc1 src 192.168.0.1 uid 0
    cache
```

`192.168.0.200` という機器は存在しませんが、`pc1` は「同じ町だから `veth-pc1` から出す」と判断しています。**道があるかどうかは、相手が実在するかとは関係なく、町名だけで決まる**ことが分かります。

:::message
`/24` は、`255.255.255.0` という書き方（**サブネットマスク**）で表されることもあります。これは「ネットワーク部を 1、ホスト部を 0 にした 32 個の並び」を 10 進数で書いたもので、意味は `/24` とまったく同じです。家庭用ルータや Windows の設定画面ではこちらの書き方がよく出てきます。

| プレフィックス長 | サブネットマスク |
|---|---|
| `/16` | `255.255.0.0` |
| `/24` | `255.255.255.0` |
| `/30` | `255.255.255.252` |
:::

## 2-3. 壊してみる① —— 相手が隣の町へ引っ越したら

`pc2` の IP アドレスを、`192.168.0.2` から `192.168.1.2` に変えます。ケーブルはつながったまま、**町名だけが変わった**状態です。

```bash
sudo ip netns exec pc2 ip addr del 192.168.0.2/24 dev veth-pc2
sudo ip netns exec pc2 ip addr add 192.168.1.2/24 dev veth-pc2
```

`ip addr del` は、付けた IP アドレスを外すコマンドです。`pc1` から新しいアドレスに `ping` を打ちます。

```bash
sudo ip netns exec pc1 ping -c 2 -W 1 192.168.1.2
```

```text
ping: connect: Network is unreachable
```

第1章で見た **`Network is unreachable`**（自分の側に道がない）です。`ip route get` で理由を聞いてみます。

```bash
sudo ip netns exec pc1 ip route get 192.168.1.2
```

```text
RTNETLINK answers: Network is unreachable
```

`pc1` のルーティングテーブルには `192.168.0.0/24` への道しかありません。`192.168.1.2` は**よその町**なので、その道は使えない。ほかに道もないので、送り出す前にあきらめたのです。

ケーブルは物理的につながっているのに、通信できない。**「ケーブルの先にいるかどうか」ではなく、「町名が同じかどうか」で、直接送るかが決まる**のがポイントです。

:::message
よその町の相手に送るには、町と町をつなぐ**ルータ**に頼む必要があります。ルータは第5章で作ります。
:::

## 2-4. 直してみる？ —— `pc1` の町を広げる

`pc1` から見て `192.168.1.2` が同じ町になるように、町の範囲を広げてみます。`/24` を `/16` にすると、ネットワーク部が前から 16 個（`192.168`）になり、`192.168.0.x` も `192.168.1.x` も同じ町に入ります。

```bash
sudo ip netns exec pc1 ip addr del 192.168.0.1/24 dev veth-pc1
sudo ip netns exec pc1 ip addr add 192.168.0.1/16 dev veth-pc1
sudo ip netns exec pc1 ip route
```

```text
192.168.0.0/16 dev veth-pc1 proto kernel scope link src 192.168.0.1
```

道が `192.168.0.0/16`（町名が `192.168` の宛先）に広がりました。これで `192.168.1.2` にも道があるはずです。

```bash
sudo ip netns exec pc1 ping -c 2 -W 1 192.168.1.2
```

```text
PING 192.168.1.2 (192.168.1.2) 56(84) bytes of data.

--- 192.168.1.2 ping statistics ---
2 packets transmitted, 0 received, 100% packet loss, time 1054ms

```

まだ通りません。ただし、**症状が変わりました**。`Network is unreachable` から **`100% packet loss`**（送ったが、返事が来ない）になっています。`pc1` 側の問題は解決して、送り出せるようになった。でも返事が来ない——ということは、問題は**相手側**にありそうです。

## 2-5. 観察する —— 相手側で何が起きているか

`pc2` の口を流れるデータを、`tcpdump` でのぞいてみます。`tcpdump` は、口を通るデータ（**パケット**）を1つずつ表示するコマンドです。

ここではターミナルを2つ使います。**もう1つターミナルを開き**、Multipass の場合は `multipass shell netlab` で同じ Ubuntu に入ってください。

**ターミナル2**（`pc2` で待ち受ける）：

```bash
sudo ip netns exec pc2 tcpdump -n -i veth-pc2 arp or icmp
```

`-n` は IP アドレスを名前に変換しない、`-i veth-pc2` は見張る口、`arp or icmp` は「ARP と ICMP（`ping` が使う通信）だけを表示する」という絞り込みです。

**ターミナル1**（`pc1` から `ping` を打つ）：

```bash
sudo ip netns exec pc1 ping -c 2 -W 1 192.168.1.2
```

ターミナル2には、次のような行が出ます。確認したら `Ctrl+C` で止めてください。

```text
tcpdump: verbose output suppressed, use -v[v]... for full protocol decode
listening on veth-pc2, link-type EN10MB (Ethernet), snapshot length 262144 bytes
19:20:56.198525 ARP, Request who-has 192.168.1.2 tell 192.168.0.1, length 28
19:20:57.254374 ARP, Request who-has 192.168.1.2 tell 192.168.0.1, length 28
19:20:58.278359 ARP, Request who-has 192.168.1.2 tell 192.168.0.1, length 28
```

意外なことに、**`ping` のデータ（ICMP）は1つも届いていません**。届いているのは `ARP, Request who-has 192.168.1.2 tell 192.168.0.1` という行だけで、しかも同じものが何度も繰り返されています。

これは「`192.168.1.2` を持っている人はいますか？ いたら `192.168.0.1` に教えて」という問い合わせです。`pc1` はこの問い合わせに返事をもらえないので、`ping` のデータを送り出せずにいます。この **ARP** の仕組みは、第3章でじっくり見ます。

今の時点で大事なのは、**なぜ `pc2` は返事をしないのか**です。`pc2` のルーティングテーブルを見てみましょう。

```bash
sudo ip netns exec pc2 ip route
```

```text
192.168.1.0/24 dev veth-pc2 proto kernel scope link src 192.168.1.2
```

```bash
sudo ip netns exec pc2 ip route get 192.168.0.1
```

```text
RTNETLINK answers: Network is unreachable
```

`pc2` は `/24` のままなので、町名は `192.168.1` です。`pc2` から見ると、問い合わせてきた `192.168.0.1` は**よその町の人**で、返事を送る道がありません。だから問い合わせを無視しているのです。

```text
pc1 (192.168.0.1/16) の考え：「192.168.1.2 は同じ町。直接送ろう」→ 問い合わせを送る
pc2 (192.168.1.2/24) の考え：「192.168.0.1 はよその町。返事を送る道がない」→ 無視する
```

**同じネットワークかどうかの判断は、それぞれの機器が自分の設定で別々に行います**。片方だけ範囲を広げても、もう片方がそう思っていなければ通信は成立しません。

## 2-6. 直す —— 両方の町をそろえる

`pc2` も `/16` にして、2台の町の範囲をそろえます。

```bash
sudo ip netns exec pc2 ip addr del 192.168.1.2/24 dev veth-pc2
sudo ip netns exec pc2 ip addr add 192.168.1.2/16 dev veth-pc2
sudo ip netns exec pc1 ping -c 2 192.168.1.2
```

```text
PING 192.168.1.2 (192.168.1.2) 56(84) bytes of data.
64 bytes from 192.168.1.2: icmp_seq=1 ttl=64 time=0.020 ms
64 bytes from 192.168.1.2: icmp_seq=2 ttl=64 time=0.026 ms

--- 192.168.1.2 ping statistics ---
2 packets transmitted, 2 received, 0% packet loss, time 1024ms
rtt min/avg/max/mdev = 0.020/0.023/0.026/0.003 ms
```

通りました。`pc2` のルーティングテーブルも `192.168.0.0/16` になっています。

```bash
sudo ip netns exec pc2 ip route
```

```text
192.168.0.0/16 dev veth-pc2 proto kernel scope link src 192.168.1.2
```

ここまでの症状を整理しておきます。

| 状態 | `pc1` から見た症状 | 原因の場所 |
|---|---|---|
| 町名が違う（`/24` 同士で `192.168.0.x` と `192.168.1.x`） | `Network is unreachable` | 自分（`pc1`）に道がない |
| `pc1` だけ `/16` に広げた | `100% packet loss` | 相手（`pc2`）に帰り道がない |
| 両方 `/16` | 通る | — |

## 2-7. 1つの町にいくつ番地があるか

町の大きさは、プレフィックス長で決まります。ホスト部が `32 - プレフィックス長` 個の 0/1 なので、`/24` ならホスト部は 8 個、番地は 2⁸ = 256 通りです。

ただし、そのうち2つは機器に付けられません。

- **ホスト部が全部 0**：ネットワークアドレス（町そのものを指す名前）。例：`192.168.0.0`
- **ホスト部が全部 1**：**ブロードキャストアドレス**（町の全員宛て）。例：`192.168.0.255`

なので、機器に付けられるのは 256 - 2 = **254 台**です。

手で計算するのが面倒なときは、Python に計算させられます。

```bash
python3 -c 'import ipaddress; n = ipaddress.ip_network("192.168.0.0/24"); print(n.network_address, n.broadcast_address, n.num_addresses - 2)'
```

```text
192.168.0.0 192.168.0.255 254
```

左から、ネットワークアドレス、ブロードキャストアドレス、機器に付けられる台数です。`/24` のところを変えると、次のようになります。

| プレフィックス長 | ネットワークアドレス | ブロードキャストアドレス | 付けられる台数 |
|---|---|---|---|
| `192.168.0.0/16` | `192.168.0.0` | `192.168.255.255` | 65534 |
| `192.168.0.0/24` | `192.168.0.0` | `192.168.0.255` | 254 |
| `192.168.0.0/30` | `192.168.0.0` | `192.168.0.3` | 2 |

プレフィックス長が**大きいほど町は小さく**なります。`/30` は機器がちょうど2台だけの町で、ルータ同士を1本のケーブルでつなぐときなどに使われます。

## 2-8. `192.168` はどこから来たのか

本書ではずっと `192.168.x.x` を使っています。これは、**家や会社の中だけで自由に使ってよい**と決められた範囲（**プライベートアドレス**）の1つです。

| 範囲 | 主な使われ方 |
|---|---|
| `10.0.0.0/8` | 大きな会社のネットワーク、クラウド |
| `172.16.0.0/12` | Docker の初期設定など |
| `192.168.0.0/16` | 家庭用ルータの初期設定 |

これ以外のアドレス（**グローバルアドレス**）はインターネット上で重複しないよう管理されているので、勝手に使ってはいけません。プライベートアドレスのままでインターネットに出ていく仕組み（NAT）は、第9章で作ります。

## 2-9. 練習問題

答えは、`ip route get` や Python で確かめてみてください。

**問1.** `10.0.5.20/16` と `10.0.200.1/16` は同じネットワークですか？

:::details 答え
**同じ**です。`/16` なのでネットワーク部は前の2つの数字で、どちらも `10.0` です。ネットワークアドレスはどちらも `10.0.0.0/16` になります。
:::

**問2.** `172.16.0.10/24` と `172.16.1.10/24` は同じネットワークですか？

:::details 答え
**違います**。`/24` なのでネットワーク部は前の3つの数字で、`172.16.0` と `172.16.1` です。2-3 と同じく、ケーブルでつないでも `Network is unreachable` になります。
:::

**問3.** `192.168.10.0/26` に付けられる機器は何台で、ブロードキャストアドレスは何ですか？

:::details 答え
**62台**、ブロードキャストアドレスは **`192.168.10.63`** です。ホスト部は 32 - 26 = 6 個なので番地は 2⁶ = 64 通り、そこからネットワークアドレスとブロードキャストアドレスの2つを引いて 62 台です。
:::

**問4.** `pc1` に `192.168.0.1/24`、`pc2` に `192.168.0.130/25` を付けました。`pc1` から `pc2` に `ping` を打つと、どんな症状になりますか？ `pc2` から `pc1` に打った場合は？

:::details 答え
- **`pc1` → `pc2`：`100% packet loss`**。`pc1` から見ると `192.168.0.130` は同じ町（`192.168.0.0/24`）なので送り出しますが、`pc2` は返事をしません
- **`pc2` → `pc1`：`Network is unreachable`**。`/25` は「前から 25 個」なので、`pc2` の町は `192.168.0.128/25`（`192.168.0.128`〜`192.168.0.255`）です。`192.168.0.1` はその外なので、`pc2` には道がありません

2-5 と同じ「片方だけ範囲が違う」状態です。実際に作って確かめてみてください。
:::

```bash
sudo ip -all netns delete
```

## まとめ

- IP アドレスは **0 と 1 が 32 個**。`/24` は「前から 24 個が**ネットワーク部**（町名）」という意味
- **ネットワーク部が同じなら同じネットワーク**。同じネットワークの相手には、ルータを通さず直接送る
- 直接送るかどうかは、ケーブルがつながっているかではなく、**自分の設定から見て町名が同じか**で決まる
- この判断は**機器ごとに別々**に行われる。片方だけ設定が違うと「送れるが返事が来ない」になる
- `ip route get <宛先>` で「その宛先にはどの道を使うか」を Linux に直接聞ける
- ホスト部が全部 0 は**ネットワークアドレス**、全部 1 は**ブロードキャストアドレス**。どちらも機器には付けない

2-5 では、`ping` のデータより先に **ARP** という問い合わせが流れていました。IP アドレスが分かっているのに、なぜわざわざ問い合わせが要るのか。次の章では、この ARP と **MAC アドレス**を見ていきます。

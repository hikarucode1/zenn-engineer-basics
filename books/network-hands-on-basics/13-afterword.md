## ここまでやってきたこと

この本では、PC 1台の中に、次のものを自分の手で作りました。

- PC（netns）と LAN ケーブル（veth）
- スイッチ（bridge）
- ルータ（`ip_forward` とルーティングテーブル）
- 家庭用ルータの NAT（nftables）
- DNS サーバ（dnsmasq）
- Web サーバ（Python の http.server）

そして、どの章でも「**つなぐ → 壊す → 観察する → 直す**」を繰り返しました。

この本を読み終えた今、次のような場面で、何を見ればいいかが分かるはずです。

| 場面 | 見るもの |
|---|---|
| `ping` が `Network is unreachable` | 自分の IP アドレス、ルーティングテーブル（`ip addr`、`ip route`） |
| `ping` が `100% packet loss` | 相手側の帰り道、途中のどこまで届いているか（`tcpdump`、`traceroute`） |
| 同じネットワークの相手に届かない | ARP 表（`ip neigh`） |
| `From <ルータ> Destination Net Unreachable` | そのルータのルーティングテーブル |
| `Could not resolve host` / `Temporary failure in name resolution` | `/etc/resolv.conf`、`dig`、DNS サーバまでの道 |
| `Connection refused` | 相手のポートで待ち受けているか（`ss -tlnp`） |
| `Timeout` | ファイアウォール、経路 |

## 自分の PC でも見てみよう

この本で使ったコマンドは、netns の中だけでなく、普段使っている Linux や、この本で使った仮想マシンそのものでも使えます。`sudo ip netns exec ...` を付けずに、次のコマンドを打ってみてください。

```bash
ip addr
ip route
ip neigh
cat /etc/resolv.conf
dig example.com
traceroute -n example.com
ss -tn
```

自分の IP アドレス、デフォルトゲートウェイ、ゲートウェイの MAC アドレス、使っている DNS サーバ、インターネット上のサーバまでの道筋、今つながっている TCP 接続——この本で作ってきたものと同じものが、本物のネットワークの中にも見つかるはずです。

本物のインターネットの `traceroute` には、プロバイダや海外のルータが何台も並びます。途中に `* * *` が出るのは、第6章で見たとおり、寿命切れの知らせを返さない設定のルータがあるからです。

## 応用編で扱いたいこと

基礎編では、ネットワークの骨組みを一通り作りました。応用編では、現場のネットワークでよく出会う、次のような仕組みを同じように手を動かしながら扱う予定です。

| テーマ | 内容 |
|---|---|
| DHCP | IP アドレスやデフォルトゲートウェイを、手で設定せずに自動でもらう仕組み |
| VLAN | 1台のスイッチを、複数の別々のネットワークに分ける |
| STP | スイッチをループ状につないでしまったときに起きることと、それを防ぐ仕組み |
| TLS / HTTPS | 第11章で丸見えだった HTTP を暗号化する仕組みと、証明書 |
| ファイアウォールの設計 | 第9・11章で少し使った nftables で、何を通して何を止めるかを設計する |
| 動的ルーティング | 第6章で手書きしたルーティングテーブルを、ルータ同士が自動で教え合う仕組み（OSPF、BGP） |
| IPv6 | この本で読み飛ばしてきた `inet6 fe80::...` の正体と、IPv4 との違い |

## 最後に

ネットワークのトラブルは、目に見えないので怖く感じます。でも、この本で見てきたとおり、中で起きていることは「**誰が、誰に、何を送り、どこまで届いたか**」の積み重ねです。`tcpdump` を打てば、それは目に見えます。

分からないことに出会ったら、この本のように**小さく作って、わざと壊して、観察してみてください**。netns なら、何度壊しても `sudo ip -all netns delete` で元通りです。

最後まで読んでいただき、ありがとうございました。

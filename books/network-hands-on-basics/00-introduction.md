## この本について

「IP アドレス」「ルーティング」「ARP」「NAT」——ネットワークの言葉は、教科書で読むと分かった気になれます。ところが、いざ「通信がつながらない」と言われると、何から調べればいいのか手が止まってしまう。

原因はシンプルで、**ネットワークを自分の手で組んで、壊して、直した経験がない**からです。本物のスイッチやルータを何台も買うのは大変ですし、会社や家のネットワークで実験して止めてしまうわけにもいきません。

そこでこの本では、**PC 1台の中に小さなネットワークを丸ごと作ります**。Linux には、1台の中に「別の PC」を何台でも作れる機能（**network namespace**）があります。これを使えば、PC・LAN ケーブル・スイッチ・ルータを全部コマンドで作れて、いくら壊しても消して作り直すだけで済みます。

## 想定読者

- IP アドレスや TCP/UDP という言葉は聞いたことがある（意味をうまく説明できなくても大丈夫）
- Linux のターミナルで `cd` や `ls` を打ったことがある
- 「なんとなく知っている」を「自分で確かめた」に変えたい

本書は『[新人エンジニアのための『本当に全部』入門](https://zenn.dev/hikarucode1/books/engineer-basics)』第9章「ネットワークの基礎」の次に読む1冊を想定しています。用語の一覧はそちらに任せ、こちらでは**実際に動かして確かめる**ことに集中します。

## この本で作るもの

章を追うごとに、ネットワークを少しずつ大きくしていきます。

| 章 | 作るもの・確かめること |
|---|---|
| 1 | PC 2台を LAN ケーブル1本でつなぐ |
| 2 | IP アドレスとサブネットの「同じネットワーク」とは何か |
| 3 | MAC アドレスと ARP —— IP アドレスだけでは届かない理由 |
| 4 | スイッチを置いて3台以上をつなぐ |
| 5 | ルータを作って、別のネットワークとつなぐ |
| 6 | ルータを2台にして、ルーティングテーブルを自分で書く |
| 7 | UDP とポート番号 |
| 8 | TCP —— 3ウェイハンドシェイクと再送 |
| 9 | NAT —— 家庭用ルータの仕組みを再現する |
| 10 | DNS —— 名前から IP アドレスを引く |
| 11 | HTTP —— Web の通信の中身を読む |
| 12 | 総まとめ：URL を開くまでに起きることを、自作ネットワークで1本通す |

各章は「**つなぐ → 壊す → 観察する → 直す**」の順で進みます。とくに「壊す」を飛ばさないでください。うまく動いた状態だけを見ても、どこが大事だったのかは分かりません。わざと1か所を壊して、どんな症状が出るかを見ておくと、現場でつながらないときに「この症状はあれだ」と思い出せるようになります。

## 環境を用意する

### 必要なもの

**Ubuntu 24.04** が動く環境を1つ用意してください。本書のコマンドと出力は、すべて Ubuntu 24.04 で実際に実行して確かめています。

ネットワーク設定をたくさん書き換えるので、**普段使っている PC やサーバで直接やるのはおすすめしません**。設定を間違えると、その PC 自体のネットワークがおかしくなることがあるからです。以下のどれかで、壊してもいい Ubuntu を用意しましょう。

| 方法 | 向いている人 |
|---|---|
| **Multipass**（おすすめ） | Mac / Windows / Linux どれでも。コマンド1つで Ubuntu の仮想マシンを作れて、要らなくなったら丸ごと消せる |
| **WSL2** | Windows で、すでに WSL2 の Ubuntu を使っている人 |
| 使っていない PC に Ubuntu を入れる | 手元に余っている PC がある人 |

:::message
WSL2 でも network namespace は使えますが、本書の動作確認は Multipass 上の Ubuntu 24.04 で行っています。WSL2 で出力が本書と違うときは、Multipass を試してみてください。
:::

### Multipass で Ubuntu を用意する

[Multipass の公式サイト](https://canonical.com/multipass) からインストールしたら、ターミナルで次を実行します。

```bash
multipass launch 24.04 --name netlab
multipass shell netlab
```

1行目で `netlab` という名前の Ubuntu 24.04 の仮想マシンを作り、2行目でその中に入ります。プロンプトが `ubuntu@netlab:~$` に変われば成功です。

この本を読み終えて要らなくなったら、次のコマンドで丸ごと消せます。

```bash
multipass delete --purge netlab
```

### 道具を入れる

Ubuntu の中で、次のコマンドを実行します。

```bash
sudo apt update
sudo apt install -y iproute2 tcpdump iputils-ping
```

それぞれの役割は次のとおりです。

| パッケージ | 中身 | 本書での使い道 |
|---|---|---|
| `iproute2` | `ip` コマンド | PC・ケーブル・IP アドレス・経路を作る、確認する |
| `tcpdump` | `tcpdump` コマンド | ケーブルを流れるデータ（パケット）を盗み見る |
| `iputils-ping` | `ping` コマンド | 相手に届くかを確かめる |

Ubuntu 24.04 には最初から入っていることが多いですが、念のため実行しておきます。ほかの道具（`nc`、`dig` など）は、使う章で入れます。

## 本書の読み方

### コマンドと出力

コマンドは次のように書きます。行頭に `$` は付けないので、そのままコピーして貼り付けられます。

```bash
ip netns list
```

コマンドを実行したときの出力は、別のブロックに分けて載せます。

```text
pc2
pc1
```

MAC アドレス（`7a:87:09:62:f1:9c` のような値）やインターフェース番号（`4:` のような行頭の数字）は、環境ごとに違う値になります。本書と一致しなくても問題ありません。

### `sudo` について

ネットワークの設定を変えるコマンドは、管理者権限が必要なので `sudo` を付けて実行します。付け忘れると `Operation not permitted` と表示されます。

### 困ったら全部消してやり直す

途中で何が何だか分からなくなったら、次のコマンドで本書で作った PC をすべて消せます。PC を消すと、その PC に挿さっていたケーブルも一緒に消えます。

```bash
sudo ip -all netns delete
```

消したら、その章の最初からやり直してください。**壊しても消して作り直せる**のが、この方法のいちばんの強みです。

それでは、1台目と2台目の PC を作りにいきましょう。
